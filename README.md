# 구스링 버전 2 — 서식 작성 도우미

외국인 주민이 **모국어 안내를 보며 입력하면, 한국어 원본 행정 서식에 바로 기재**되는 구스링 버전 2입니다. ([gusring_prototype](https://github.com/gusring/gusring_prototype)에서 옮겨 왔습니다.)
가족관계 신고서부터 하나씩 늘려 가고 있습니다 (지금: v1 서식 1·2·3·4·5·6·7·8번).

## 화면 흐름
`#/` 언어 선택 → `#/list` 문서 선택 → `#/form/birth-report` 서식 작성 (`#/map` 민원실 지도)

언어 선택·문서 선택 화면과 헤더·지도는 [gusring-web](https://github.com/gusring/gusring-web)을 그대로 옮겼습니다. 헤더의 의견 보내기는 구글 폼 대신 구스링 백엔드로 보냅니다.
처음에 고른 언어로 서식 작성 화면의 안내와 라벨이 모두 표시됩니다.

## 서식 작성 화면
1. 한국어 원본 서식 이미지 위, 입력해야 하는 칸마다 번호 토글이 표시됩니다.
2. 번호를 누르면 바텀시트가 열리고, 그 칸의 의미와 작성법을 모국어(ko/en/zh/ja/vi)로 안내합니다.
3. 입력하는 즉시 한국어 서식의 해당 칸에 기재됩니다. 선택형 항목은 ○/✓로, 국가는 한국어 국가명으로 변환됩니다.
4. "완성 서식 보기"에서 이미지 저장 또는 A4 인쇄. 입력값은 브라우저(localStorage)에만 저장됩니다.
5. 여러 쪽 서식은 왼쪽 아래 「‹ 2쪽 중 1쪽 ›」으로 쪽을 넘깁니다. 번호와 이전·다음은 쪽을 이어서 셉니다(다른 쪽의 칸을 고르면 그 쪽으로 넘어감). 완성 서식 보기는 모든 쪽을 보여 주고, 이미지 저장은 쪽을 위아래로 이어 붙인 PNG 한 장, 인쇄는 쪽마다 A4 한 장입니다.

## 실행
```bash
npm install
npm run dev
```

로컬 [gusring-server](https://github.com/gusring/gusring-server)에 붙일 때 (기본은 운영 `https://api.gusring.kro.kr`):
```bash
VITE_GUSRING_API=http://localhost:4000 npm run dev
```

## 구스링 백엔드 연결
`src/lib/gusring-api.ts`는 gusring-server `examples/gusring-api.ts`와 같은 파일입니다 (gusring-web `src/shared/gusring-api.ts`와도 같음). 고칠 때는 원본을 고치고 복사합니다.
- 이용 기록: 화면 진입·언어 선택·검색·카테고리, 서식 작성 단계(`form_view` `fill_start` `field_open` `fill_preview` `fill_png_save` `fill_print` `fill_reset` `detail_time`)를 `formKey`(서식 id)·`formNo`(gusring-web 서식 번호)와 함께 보냅니다. **칸에 적은 값은 보내지 않습니다.**
- 의견 보내기: 헤더 버튼 → `POST /api/v1/feedbacks`. 서식 화면에서 보내면 서식 id·서식 번호·칸 id가 같이 갑니다.
- 운영 서버 CORS에 이 사이트 주소가 등록돼 있어야 의견 보내기가 됩니다 (이용 기록은 text/plain이라 등록 없이도 도착).

## 서식 추가하기
`src/forms/{formKey}.ts`에 `FormDef`를 하나 더 만들고 `src/forms/catalog.ts`에 v1 서식 번호(`formNo`)·카테고리·설명과 함께 등록하면 문서 선택 화면에 나타납니다. `formKey`는 영어 kebab-case(예: `birth-report`)입니다.
- 원본 이미지: `public/forms/{formKey}_ko.png`, 2쪽은 `{formKey}_ko_2.png` (파일 이름에 한글·공백 금지)
- `pages`: 쪽마다 `{ image, width, height }`. 1쪽 서식도 한 장짜리 배열
- 서식 하나를 목록의 여러 항목이 같이 쓰면 항목마다 `key`(주소·저장 이름)와 `title`을 따로 둡니다

칸마다 필요한 것은
- `page`: 칸이 있는 쪽 (1부터, 없으면 1쪽). 아래 좌표는 그 쪽 이미지 기준
- `area`: 서식 이미지 위 탭 영역 (원본 이미지 픽셀 좌표)
- `input`: 입력 종류(`text` · `date` · `datetime` · `choice` · `country` · `idnum`)와 값을 쓸 위치
  - `date`: 「년 월 일」이 인쇄된 칸은 `boxes`(숫자만), 빈 칸은 `box` 하나(「1990년 1월 1일」)
  - `choice`: `multiple: true`면 여러 개 고르기 (신고인 출석여부 등)
- `label` · `help`: 5개 국어 안내

`fields`의 순서가 번호와 이전·다음 순서입니다. 1쪽 위→아래, 2쪽 위→아래 순으로 둡니다. 두 사람이 나란히 있는 표(양부·양모 등)는 한 사람 칸을 다 채운 뒤 다음 사람으로 넘어가게 둡니다.

가족관계 신고서들이 같이 쓰는 칸(이름·한자·주민등록번호·등록기준지·주소·본·신고인·제출인·인구동향조사 학력)은 `src/forms/common.ts`에서 좌표만 넘겨 만듭니다. 안내 문구도 거기서 같이 관리합니다.
- 번호 토글은 칸 이름(라벨)을 가리지 않도록 값 칸 왼쪽 위에 둡니다. 선택지 상자와 겹치면 `badge: 'margin'`(표 오른쪽 여백)
- 글자는 칸 폭에 맞춰 줄어들고, 한 줄로 16px보다 작아지면 두 줄로 나눕니다
- 서명·날인, 공무원 기재란, 접수번호·처리란은 입력받지 않습니다

## 확인이 필요한 것
- 외국인 이름의 한글 표기 기준 (현재 안내: 여권·외국인등록증 이름을 한글로 옮겨 적기)
- 컴퓨터로 기재해 출력한 서식을 법원 송부용으로 그대로 받는지
- zh/ja/vi 안내 문구 원어민 검수
- 출생신고서 ja 안내·선택지에 한글이 섞여 있음 (세대주 관계 예시 「홍길동 의 자」, 「息子 (자)」 등)
- **필수 표시 기준**: 1·2·3·5·6·7·8번은 서식·작성 방법에 '필수'라는 말이 없어 모든 칸을 선택으로 두었습니다. 사망신고서의 눈표(*)는 "통계청에서도 수집하는 자료"라는 뜻이라 필수로 보지 않았습니다. 창구에서 꼭 받는 칸(본인 이름·신고인 이름 등)을 필수로 할지 정해 주세요

### 서식별
- **1 가족관계등록 창설신고서**: 신고인 자격 「기타」의 예시(누가 될 수 있는지)는 작성 방법에 없어 안내하지 않음. 한국어 작성 방법만 근거로 함(별도 안내 이미지 1장은 서식과 같은 내용)
- **2 사망신고서**: 서머타임 기간 사망 시 「(서머타임 적용)」은 칸이 따로 없어 종이에 직접 적도록 안내함. 사망장소 구분 ⑨ 「병원 이송 중 사망」 번역이 맞는지 원어민 검수 필요
- **3 인지(친권자 지정)신고서**: 피인지자 성명 칸은 「(성) / (명)」이 검은 글씨로 인쇄돼 있어 그 아래 줄에 씀 — 창구에서 받아 주는지 확인 필요. ③의 ( ) 칸은 작성 방법에 적힌 네 가지(조정성립 등) 중에서 고르게 함. ⑦ 기타사항의 경우는 작성 방법의 일부만 예시로 옮김
- **5 파양신고서**: 「⑧ 신고인 출석여부」의 뜻(창구에 직접 나온 신고인)은 작성 방법에 설명이 없어 칸 이름으로만 안내함
- **6 개명신고서**, **7 성·본 변경신고서**: 서식 아래 작성 방법만 근거로 함. 7번 「본(本)」 설명(시조의 고향)은 일반 설명이라 창구 확인 필요
- **8 입양신고서**: 출석여부의 「법정대리인(①부 ②모 ③후견인)」을 「법정대리인」+「그중 부·모·후견인」 두 번 고르게 함 — 창구에서 이렇게 표시하는 게 맞는지 확인 필요. 신고인 전화·이메일은 칸 높이가 낮아(27px) 사람마다 번호 하나로 함께 받음
